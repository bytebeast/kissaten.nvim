1. INTRODUCTION                                         *kissaten-introduction*

Kissaten combines Tokyonight's crisp cool backgrounds and clear structure
colors with Catppuccin's softer warm accents and layered surfaces. Every
syntax color is checked against WCAG AA (4.5:1) in every style, and comments
are kept at 4:1 or better so they stay readable on any screen.

Requires Neovim 0.9 or newer. Tested on 0.9, 0.10, 0.11 and 0.12.

==============================================================================
2. STYLES                                                     *kissaten-styles*

  `kissaten-morning`     light   bright paper with deep, AA-contrast inks
  `kissaten-afternoon`   dark    slate blue, softer mid-tone
  `kissaten-evening`     dark    cool navy with warm accents (default)
  `kissaten-midnight`    dark    near-black, for low-light sessions
  `kissaten-graveyard`   dark    black, for OLED screens and dark rooms

`:colorscheme kissaten` follows 'background': dark loads `style`, light
loads `light_style`. Changing 'background' while a kissaten style is active
switches to the matching variant and remembers the last one used.

==============================================================================
3. SETUP                                                       *kissaten-setup*

lazy.nvim / LazyVim: >lua
  return {
    { "bytebeast/kissaten.nvim", lazy = false, priority = 1000, opts = {} },
    { "LazyVim/LazyVim", opts = { colorscheme = "kissaten" } },
  }
<
Plain Neovim: >lua
  require("kissaten").setup({ style = "midnight" })
  vim.cmd.colorscheme("kissaten")
<
Calling `setup()` is optional; defaults are used otherwise.

==============================================================================
4. CONFIGURATION                                              *kissaten-config*

Defaults: >lua
  require("kissaten").setup({
    style = "evening",        -- afternoon|evening|midnight|graveyard
    light_style = "morning",  -- used when background=light
    transparent = false,      -- don't paint the editor background
    terminal_colors = true,   -- set g:terminal_color_0..15
    dim_inactive = false,     -- darken non-current windows
    contrast = "normal",      -- "high": lift comments, line numbers, UI hints
    subtle_comments = false,  -- true | 0..1 | { fade = 0.7, docstrings = true }
    styles = {
      comments = { italic = true },
      keywords = { italic = true },
      functions = {}, variables = {}, parameters = {},
      types = {}, strings = {}, constants = {},
      sidebars = "dark",      -- "dark" | "normal" | "transparent"
      floats = "dark",        -- "dark" | "normal" | "transparent"
    },
    no_italic = false, no_bold = false, no_underline = false,
    bright_borders = false,   -- accent-colored float borders
    lualine_bold = false,
    on_palette = function(palette, style) end,
    on_colors = function(colors) end,
    on_highlights = function(highlights, colors) end,
    plugins = { all = nil, auto = true },
  })
<
                                                     *kissaten-subtle-comments*
`subtle_comments` fades code comments toward the background so they recede
behind the code. `fade` goes from 0 (off) to 1 and is measured in contrast,
so a value looks the same in every style: 0.5 gives about 3:1, 0.7 about
2.5:1, and 1 stops at 1.6:1. `true` means 0.5. Docstrings fade too unless
`docstrings = false`. TODO badges, inlay hints and the statusline are not
affected. >lua
  subtle_comments = 0.5
  subtle_comments = { fade = 0.7, docstrings = false }
<
Invalid values never break your editor: kissaten reports them once with
|vim.notify()| and falls back to the default for that option.

5. OVERRIDES                                               *kissaten-overrides*

There are three layers, applied in order:

`on_palette(palette, style)`    change raw colors before anything is derived
`on_colors(colors)`             re-point semantic roles (see |kissaten-roles|)
`on_highlights(hl, colors)`     final say over any highlight group

Changing a role is usually what you want, because every group, language
and plugin that uses it follows: >lua
  on_colors = function(c)
    c.syn.parameter = c.yellow     -- parameters in yellow everywhere
    c.diag.hint = c.lavender
  end,
<
Per-style tweaks: >lua
  on_palette = function(p, style)
    if style == "graveyard" then p.bg = "#000000" end
  end,
<
Palettes can also set `_tint` (default 1): how strongly accents tint
backgrounds such as selection, search, diff and diagnostics. `graveyard`
uses 1.15 so these stay as visible on black as they are in midnight; raise
it if you make your own background darker.

Highlight overrides accept any |nvim_set_hl()| attributes, a `link`, or a
string as shorthand for a link: >lua
  on_highlights = function(hl, c)
    hl.LineNr = { fg = c.overlay0 }
    hl.CursorLineNr = { fg = c.yellow, bold = true }
    hl["@variable.member"] = "@property"
  end,
<
==============================================================================
6. COLOR ROLES                                                 *kissaten-roles*

`require("kissaten").colors()` returns the active colors. Main roles:

  colors.syn.keyword          purple   keywords
  colors.syn.func             blue     functions and methods
  colors.syn.func_builtin     cyan     builtin functions
  colors.syn.type             yellow   types, classes, interfaces (italic)
  colors.syn.parameter        maroon   parameters
  colors.syn.property         teal     fields and properties
  colors.syn.string           green    strings
  colors.syn.number           orange   numbers, constants, booleans
  colors.syn.variable_builtin red      self, this, super
  colors.syn.module           lavender modules and namespaces
  colors.syn.macro            pink     macros, decorators, escapes
  colors.syn.operator         sky      operators

Also `colors.ui.*`, `colors.diag.*` (error/warn/info/hint/ok),
`colors.git.*`, `colors.diff.*`, `colors.rainbow[1..8]` and
`colors.terminal.*`. See `lua/kissaten/colors.lua` for the full list.

==============================================================================
7. PLUGIN INTEGRATIONS                                       *kissaten-plugins*

With lazy.nvim (and vim.pack on 0.12+), only the integrations for plugins
you actually have are loaded. Without a supported plugin manager every
integration is loaded. Force one on or off by module or repo name: >lua
  plugins = { all = false, telescope = true, ["fzf-lua"] = false }
<
Run |:checkhealth| kissaten to see which integrations are active.

==============================================================================
8. COMMANDS AND API                                              *kissaten-api*

                                                                    *:Kissaten*
:Kissaten [style]       switch style (with completion), or reload
:Kissaten info          same as `:checkhealth kissaten`

`require("kissaten").setup(opts)`      store options
`require("kissaten").load(opts, style)` apply now, returns colors, groups
`require("kissaten").colors(style?)`    colors table for your own config

Lualine themes: `kissaten` (follows the active style) and
`kissaten-<style>`. LazyVim's default `theme = "auto"` picks them up.

==============================================================================
9. EXTRAS                                                     *kissaten-extras*

Matching themes for Alacritty, bat, delta, eza, fzf, Ghostty, k9s, Kitty,
lazygit, tmux, WezTerm and Zettlr live in `extras/`, in all five styles (k9s
also has `_transparent` skins). Install steps are in the README, with full
guides for bat, eza, k9s and Zettlr in `extras/<tool>/README.md`;
`extras/fonts/README.md` recommends coding fonts (the screenshots use
JetBrains Mono Nerd Font) and shows how to set them up, including ligatures.
Regenerate after changing a palette: >sh
  nvim --headless -u NONE -l scripts/build_extras.lua
<
